# 基础概念

# DP（数据并行）中的关键概念区分



## 1. **基本概念定义**

```python
# 在分布式训练中
world_size = 总进程数              # 所有节点的总进程数
world_rank = 全局进程排名           # 0 到 world_size-1

local_size = 单节点进程数          # 当前节点上的进程数
local_rank = 节点内进程排名         # 当前节点内的排名，0 到 local_size-1

node_rank = 节点排名               # 节点编号，0 到 节点总数-1
num_nodes = 节点总数               # 参与训练的总节点数
```

## 2. **DP同节点场景（单机多卡）**

### **配置示例**

```python
# 假设：1个节点，8个GPU
world_size = 8
num_nodes = 1
local_size = 8
node_rank = 0

# 进程分布：
# GPU0: world_rank=0, local_rank=0
# GPU1: world_rank=1, local_rank=1
# ...
# GPU7: world_rank=7, local_rank=7
```

### **通信特点**

```python
# 1. 使用共享内存通信
communication = "intra_node"  # 节点内通信
latency = "极低"               # 微秒级别
bandwidth = "极高"             # 数百GB/s

# 2. NCCL优化
NCCL_ALGO = "Ring" or "Tree"  # 环形或树形算法
NCCL_PROTO = "LL/LL128"       # 低延迟协议
```

## 3. **DP跨节点场景（多机多卡）**

### **配置示例**

```python
# 假设：4个节点，每个节点8个GPU
world_size = 32
num_nodes = 4
local_size = 8
node_rank = 0-3  # 取决于节点

# 进程分布：
# 节点0: world_rank=0-7,   local_rank=0-7
# 节点1: world_rank=8-15,  local_rank=0-7
# 节点2: world_rank=16-23, local_rank=0-7
# 节点3: world_rank=24-31, local_rank=0-7
```

### **通信特点**

```python
# 1. 网络通信
communication = "inter_node"  # 节点间通信
latency = "较高"               # 毫秒级别
bandwidth = "有限"             # 受网络限制

# 2. NCCL优化
NCCL_ALGO = "Tree"            # 多使用树形算法
NCCL_PROTO = "SIMPLE"         # 简单协议
```

# 并行维度的常见组合模式

在真实的大模型训练中，很少单独使用某个维度，通常是**特定组合**。让我按**常见程度和使用场景**来分析：

## 1. **最经典组合：DP + TP**

### **适用场景**

- **中等规模模型**（10B-100B参数）
- **单机/多机训练**
- **资源充足，追求训练速度**

### **架构示例**

```python
# 配置示例
world_size = 32
dp_size = 8      # 数据并行
tp_size = 4      # 张量并行
# 设备数: 8×4=32

# 排列：先TP，后DP
设备映射：设备i = DP组(i//tp_size) 中的 TP分片(i%tp_size)
```

### **使用框架**

- **Megatron-LM** 的经典配置
- **DeepSpeed** 的常见用法
- 大部分开源模型训练

## 2. **大模型标配：DP + TP + PP**

### **适用场景**

- **超大模型**（100B-1T+参数）
- **多机多卡**，显存不够
- **需要处理超长序列**

### **架构示例**

```python
# GPT-3 175B 训练配置
world_size = 1024
dp_size = 32     # 数据并行
tp_size = 8      # 张量并行  
pp_size = 4      # 流水线并行
# 设备数: 32×8×4=1024

# 排列顺序：PP → TP → DP（从高到低）
# 物理理解：模型分4段(PP)，每段分8片(TP)，每片复制32份(DP)
```

### **典型通信模式**

```python
# PP组内：前向/后向流水线通信
# TP组内：All-Gather/Reduce-Scatter
# DP组间：All-Reduce梯度同步
```

## 3. **特殊优化组合**

### **3.1 TP + SP（处理长序列）**

```python
# 处理超长文本
tp_size = 2      # 拆分模型权重
sp_size = 2      # 拆分序列长度
# 适合：长文档理解、代码生成

# 示例：序列长度32768，拆成2个16384
# 设备0: 序列前一半 + 模型前半权重
# 设备1: 序列后一半 + 模型后半权重
```

### **3.2 DP + EP（MoE模型）**

```python
# 混合专家模型
dp_size = 4      # 数据并行
ep_size = 8      # 专家并行（8个专家）
# 设备数: 4×8=32

# 设备0: DP组0，专家0,1,2,3,4,5,6,7中的某几个
# 设备1: DP组0，其他专家
```

### weakref

弱引用 **weakref 模块允许Python 程序员创建对象的弱引用**。 在下文中，术语所指对象表示弱引用所指向的对象。 对象的弱引用不能保证对象存活：当所指对像的引用只剩弱引用时， 垃圾回收 可以销毁所指对象，并将其内存重新用于其它用途。

弱引用（weakref）是一种特殊的引用机制，它在不增加对象引用计数的前提下允许程序访问对象，从而解决内存泄漏问题并优化资源管理。其核心价值在于不影响对象的生命周期，当对象不再被强引用时，垃圾回收器（GC）可自动回收其内存 。
